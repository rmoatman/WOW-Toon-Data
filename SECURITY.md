# Security

This is an unofficial, non-commercial portfolio project. It handles account
logins and links to Battle.net, so it's built with these practices in mind.

## Secrets & configuration

- **No secrets live in this repository or its history.** All sensitive values —
  the MongoDB connection string, JWT signing secret, token-encryption key,
  Battle.net client ID/secret, and SMTP credentials — are supplied at runtime via
  **environment variables** (set in the hosting dashboard, and locally in
  `server/.env`, which is git-ignored and never committed).
- The tracked `*.env.example` files contain **placeholders only**.
- `render.yaml` never contains secret values (they are `sync: false`, entered in
  the Render dashboard, or generated by Render).
- If you fork/deploy this, generate your own random `JWT_SECRET` and
  `TOKEN_ENCRYPTION_KEY` and set every Blizzard/DB/email value in your host's
  environment — do not commit them.

## How sensitive data is handled

- **Passwords** are hashed with bcrypt; the hash is never returned to clients.
- **Auth** uses a signed JWT in an `httpOnly`, `Secure`, `SameSite=Lax` cookie
  (first-party, single-origin), not readable by JavaScript.
- **Battle.net access tokens** are encrypted at rest (AES-256-GCM) using
  `TOKEN_ENCRYPTION_KEY`; they are never sent to the client.
- **OAuth** uses the authorization-code flow with a signed `state` and a
  short-lived nonce cookie for CSRF protection. The app never sees your Blizzard
  password.
- **Password-reset tokens** are stored only as SHA-256 hashes.

## The demo account

A read-only seeded demo account may exist so the app can be explored without a
Blizzard account. It is intentionally low-privilege (`isDemo` blocks account
deletion and password reset). Do not reuse any demo credentials elsewhere.

## Reporting a vulnerability

Please report security issues privately by email to **raemarie.oatman@gmail.com**
rather than opening a public issue. Include steps to reproduce; you'll get a
response as soon as reasonably possible.

Secret Scanning and Push Protection are enabled on this repository to help catch
accidentally committed credentials.
